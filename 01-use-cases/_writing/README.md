# _writing

Three examples of writing with AI. The seminar paper is laid out as the
humanist has always worked: the **books** you read, the **notebook** you
keep, the **paper** you publish, which is the inputs → operations → outputs
model in its oldest form and the reason this folder sorts first. The other
two use the repository's usual `inputs/`, `operations/`, `outputs/`.

| Example | What you will do | Size |
|---|---|---|
| [`01-seminar-paper/`](01-seminar-paper/) | The whole arc: brief, reading notes, brainstorm, thesis, quote bank, outline, draft, judges, your feedback, provenance record. Eleven steps, three of them yours alone. | A term paper |
| [`02-quotes-and-outlines/`](02-quotes-and-outlines/) | Only the notebook's first movements: pull the passages out of a text, see its skeleton, sketch what a paper could be. Worked on Grice's "Logic and Conversation." | An afternoon |
| [`03-word-clouds/`](03-word-clouds/) | No model at all: Wordle's 2008 algorithm rebuilt in Python and run on the Preface to *Dorian Gray*, counts beside the picture. For contrast with the two above, and for the pleasure of it. | Ten minutes |

Start with the second if you want to see the model read a text in front of
you. Start with the first if you have a paper due. The third is what counting
looks like with nothing reading at all; it is here so the difference shows.

The first two obey the same rules: read texts whole; no invented quotations,
every one findable in `context/`; the model drafts and you decide; and every
use of AI is documented, because this course's policy asks for exactly that.
The third has no model to document; its counts are the record.
